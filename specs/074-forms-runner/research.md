# Research 074
One non-obvious choice: the `feedback_forms` table has no `slug` column, so the route's `[slug]` segment is parsed in-route as `${kind}-${audience}-${version}` and resolved through the existing `feedback_forms_kind_audience_version_uq` index. This keeps the schema locked, avoids a `slug` column migration, and is stable — the (kind, audience, version) triple is already the natural key. Trade-off: slugs are not free-form (e.g. you can't have `school-visit` because `school` and `visit` parse to kind and audience), but that's exactly what the unique index encodes anyway.
A second choice: `feedback_responses.pairing_id` is NOT NULL in the schema, but the brief asks for a "public-ish" runner. Resolved by threading `?pairingId=` from the catalogue link into a hidden input inside the renderer's form, with a clear inline error when the action runs without one (no silent malformed insert).

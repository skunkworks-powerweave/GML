# Research 118

- **Server actions vs. client components.** The detail page is a server component fetching from Drizzle; adding a client boundary just for button onClick handlers would cost an extra bundle, lose the server-only `db` handle, and require a separate fetch surface. Next.js Server Actions (`"use server"` in `actions.ts`) let native `<form action={fn}>` posts mutate without any client JS — perfect for v1.
- **Concurrent `meetings_count` writes.** Two mentors logging meetings within the same second on the same pairing would race a `SELECT meetings_count → +1 → UPDATE` round-trip. The action uses `sql\`${mentorPairings.meetingsCount} + 1\`` inside `db.update` to push the increment into the SQL layer, which Postgres handles atomically.
- **Form slug derivation.** Spec 074 baked `${kind}-${audience}-${version}` as the URL contract. Quarter index → kind is `{1: baseline, 2: progress_1, 3: progress_2, 4: final}` per `feedbackKindEnum` in `enums.ts`. Audience defaults to `mentor` (the page is mentor-first); version is `"1"` per the seed scripts.
- **WhatsApp link safety.** `wa.me/<phone>` strips all non-digits via `replace(/[^0-9]/g, "")`. We require at least 10 digits before rendering the link; otherwise we render a disabled-styled chip so the UI is honest about the missing data.
- **Commitments column deferred.** The JSX prototype shows a static four-item commitments register. The schema has no `commitments` column on `mentor_pairings`. We deliberately do NOT add the migration in this spec (Tier C is button-wiring, not schema work). Instead, `toggleCommitmentAction` writes an audit row with `{index, done, text}`. The follow-up migration adds `commitments jsonb DEFAULT '[]'::jsonb`, then backfills from `audit_log WHERE action='mentor.commitment.toggled'` ordered by created_at (last write wins per `index`).
- **Internal messaging is `/inbox?to=`.** No internal messaging system exists; the JSX prototype's "Message" button is aspirational. We point at `/inbox?to=<teacher.userId>` so the click goes somewhere meaningful instead of `href="#"`. Future spec adds threaded messaging.
- **"Complete pairing" role gate.** Per the v2 spec (027) RBAC matrix, super_admin + programme_admin are the only roles that can transition pairings between states. The action calls `requireRole(["programme_admin", "super_admin"])` which `redirect`s to `/forbidden` on a fail — never silently no-ops.
